## 是什麼 · What it is

`/proc` 目錄（process filesystem）是 Linux kernel 實作的**虛擬檔案系統**，`/proc/cpuinfo`、`/proc/meminfo`、`/proc/uptime` 裡的「檔案」實際上都是 kernel 動態生成的字串，讀的當下才計算，沒有佔磁碟。

在 kernel module 裡建立自己的 `/proc/myinfo`：

```c
#include <linux/proc_fs.h>
#include <linux/seq_file.h>

static int myinfo_show(struct seq_file *m, void *v) {
    seq_printf(m, "hello from /proc/myinfo\n");
    return 0;
}

static int myinfo_open(struct inode *inode, struct file *file) {
    return single_open(file, myinfo_show, NULL);
}

static const struct proc_ops myinfo_fops = {
    .proc_open  = myinfo_open,
    .proc_read  = seq_read,
    .proc_lseek = seq_lseek,
    .proc_release = single_release,
};

static int __init mymod_init(void) {
    proc_create("myinfo", 0444, NULL, &myinfo_fops);
    return 0;
}
static void __exit mymod_exit(void) {
    remove_proc_entry("myinfo", NULL);
}
```

**`seq_file` 介面**（現代做法）讓你不用管緩衝區切分（page boundary），kernel 幫你處理大型輸出；`seq_printf` 語法跟 `printf` 相同。

::: en
`/proc` is a **virtual filesystem** — files like `/proc/cpuinfo` are dynamically generated by the kernel on each read, taking no disk space. To expose data via `/proc/myinfo` from a module, use `proc_create` with a `proc_ops` table wired to `seq_file` helpers (`single_open`/`seq_printf`/`single_release`). The `seq_file` layer handles page-boundary buffering automatically — you just call `seq_printf`.
:::

## 為什麼重要 · Why it matters

| | 字元裝置 (`misc_register`) | /proc (`proc_create`) |
|--|--------------------------|----------------------|
| 適用場景 | read/write 雙向、bitmask 控制 | 唯讀診斷資訊 |
| 自動建節點 | `/dev/kfetch` | `/proc/myinfo` |
| 需要 major/minor | 否（MISC_DYNAMIC_MINOR）| 否 |
| 標準存取方式 | `open/read/write` syscall | `cat /proc/myinfo` |

`kfetch` 作業選字元裝置是因為需要 write（設定 bitmask）。如果只是讀取 kernel 狀態，`/proc` 更簡單，`seq_printf` 就夠了。

::: en
`kfetch` uses a character device because it needs `write` (to set the bitmask). For **read-only** kernel state exports, `/proc` is lighter — no `copy_to_user` needed, `seq_printf` outputs directly into the kernel buffer that the VFS layer copies to user-space.
:::

## 一句話帶走 · Takeaway

想從 kernel module 輸出唯讀診斷資訊，用 `/proc` + `seq_file` 比字元裝置更輕量；想要可寫的雙向通道，才換字元裝置。

::: en
For read-only kernel diagnostics, `/proc` + `seq_file` is lighter than a character device. Only reach for a character device when you also need `write`.
:::

動態規劃 Dynamic Programming

把大問題拆成重疊的小問題,每個只算一次、記下來重用。

給原本不熟的人的 10 分鐘入門 · 來源:5 篇公開 CC 教材

先看痛點

暴力遞迴為什麼慢?

算費氏數 fib(n)=fib(n-1)+fib(n-2),直接遞迴會把同一個子問題重算非常多次:

fib(5) 要 fib(3) 兩次、fib(2) 三次… → 整體 指數級 O(φⁿ)

關鍵觀察:工作量爆炸,是因為一直重算算過的東西。

來源:dp-wikipedia、dp-erickson(ch.3)
核心點子

記下來,就不用重算

記憶化 (memoization):第一次算某個子問題,就把答案存進表;之後要用,直接查表。

fib(5):每個 fib(k) 只算一次 → 從 O(φⁿ) 降到 O(n)

這就是動態規劃的靈魂:相異子問題數 × 每次轉移成本,不再有重算。

來源:dp-wikipedia、dp-erickson
什麼題目能用

DP 成立的兩個前提(缺一不可)

① 重疊子問題

同一個子問題會被反覆用到 → 記下來才有省。
若子問題都不同(如 merge sort 左右半)→ 那是分治,不是 DP。

② 最優子結構

原問題的最優解,能由子問題的最優解拼出來 → 才能由小解推大解。

口訣:「會重複算」＋「大解由小解的最優拼出」 → 才是 DP 題。

來源:dp-wikipedia、dp-erickson
兩種寫法,同一條遞迴

記憶化 vs. 製表

記憶化 Top-down

照遞迴自然寫,算過就存、再用查表。
只算真正用到的狀態、貼近思路;代價:遞迴堆疊+查表開銷。

製表 Bottom-up

按依賴順序由小到大迭代填表,不遞迴。
無堆疊、常數小、可壓空間;代價:要想清填表順序。

時間複雜度同階;選哪個看狀態是否稠密、要不要空間壓縮。

來源:dp-cp-algorithms
動手流程

設計一題 DP 的 6 步

  • 定狀態:一個子問題用什麼參數唯一描述?
  • 寫轉移:大狀態最優解 = 哪些小狀態怎麼組合?
  • 定邊界:最小子問題的答案(base case)。
  • 定求值順序:記憶化(遞迴)或製表(由小到大)。
  • 讀答案 + 還原:最終狀態即解;要輸出方案就回溯。
  • 算複雜度:≈ 狀態數 × 單次轉移成本。
來源:dp-erickson、dp-cp-algorithms
經典例

0/1 背包 Knapsack

n 件物品各有重量/價值,背包容量 W,求不超重的最大總價值。

  • 狀態 dp[i][w] = 前 i 件、容量 w 時的最大價值
  • 轉移 = max(不取第 i 件 dp[i-1][w], 取 dp[i-1][w-wᵢ]+vᵢ)
  • 複雜度 O(nW)(偽多項式:隨 W 的數值而非位數)

同套路也解:最長遞增子序列 LIS、編輯距離 edit distance。

來源:dp-knapsack-wikipedia、dp-knapsack-cp
別硬套

什麼時候「不」用 DP

子問題不重疊

→ 用分治(divide & conquer)。沒有重算,DP 沒省處。

局部最優=全域最優

→ 用貪婪(greedy),更簡單。DP 是「貪婪不成立時」的保險。

記住 DP 不是越多越好——先確認兩個前提成立。

來源:dp-wikipedia、dp-erickson

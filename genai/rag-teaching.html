問題起點

LLM 有兩個根本弱點

📅

知識截止日（Cutoff）

訓練資料有截止日期。2023 年訓練的模型不知道 2024 年的事——它的「大腦」在訓練後就凍結了。

👻

幻覺（Hallucination）

模型為了生成流暢文字，會編造聽起來合理但錯誤的「事實」。它自信地說謊，卻不知道自己在說謊。

💡

直覺解法： 給模型「外部記憶體」——回答前先查相關文件，把查到的內容當作依據再生成答案。這就是 RAG。

Lewis et al., NeurIPS 2020

關鍵問題

查到了，不代表說對了

Lewis 2020 的未解缺口： RAG 把答案「條件在」檢索到的段落上——但這不等於答案「忠於」那個段落。 模型帶著訓練時的「舊記憶」，可能無視找到的文件自己編造答案（parametric leak）。

解法方向

類比：你給學生一本教科書（=檢索），讓他回答問題——但他可能還是用他從小背的錯誤知識作答，完全沒看書。
「有書 ≠ 看書 ≠ 答案來自書」是三個不同的驗證關卡。

Asai et al., ICLR 2024

Self-RAG：讓模型學會自我批判

核心創新：Reflection Tokens

  • 🔎 Retrieve：要不要去查？（按需，非強制）
  • 📊 IsRel：查到的段落相關嗎？
  • ✅ IsSup：我的答案有被段落支持嗎？
  • 🎯 IsUse：整體回答有用嗎？

效果

在 open-domain QA、事實驗證、long-form 任務上贏過 ChatGPT 和標準 RAG，提升 factuality 與引用準確度。

限制（和我的理解）

問題 1：非決定性
Reflection token 是機率輸出，每次跑結果不同

問題 2：非獨立
同一個模型「生成答案」又「評自己的答案」——錯誤知識會同時污染兩者（相關誤差）

比喻：讓同一個學生寫考卷、又批自己的考卷——他的盲點會讓兩件事都錯。

Es et al., EACL 2024

RAGAS：自動評估 RAG 系統

🎯

Faithfulness

答案每條陳述，是否被檢索段落支持？
= 量「答案忠不忠於來源」

💬

Answer Relevance

從答案反推它在回答什麼問題，與原問題比對

📚

Context Precision

檢索到的句子中，真正與問題相關的比例

優點

  • ✅ 不需要人工標準答案（Reference-free）
  • ✅ 可自動化，快速跑進 CI pipeline
  • ✅ 與人類評分相關性高

限制

  • ⚠ LLM-as-judge：每次跑分數可能不同
  • ⚠ Prompt 敏感：換 prompt 分數就變
  • ⚠ 每次評分需付 API 費用
進階：Trustworthy RAG

為什麼需要決定性驗證閘門？

Self-RAG 和 RAGAS 都問了「答案有被支持嗎？」——但答案是機率輸出，每次跑可能不同。 真實系統（尤其教育/醫療）需要決定性、可複現、$0 判官的驗證。

方式 非決定性 成本
RAGAS 高 API $
Self-RAG 中 $0
Embedding Gate 零 $0

Embedding 餘弦閘門

答案 → 向量 + 來源 → 向量 → cosine similarity
  • cos ≥ 0.42 → ✅ PASS（有接地）
  • cos 0.3–0.42 → ⚠️ WARN（脈絡外）
  • cos < 0.3 → ❌ FAIL（幻覺）
凍結閾值 → variance = 0，完全可複現

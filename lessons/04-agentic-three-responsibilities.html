代理時代工程師的三職責：指定意圖 → 評估軌跡 → 收回控制

當 AI agent 能自己跨多步執行，工程師的工作從「自己寫 code」變成三件事。

是什麼

以前寫程式是你一行一行敲。當 AI agent 能**自己規劃、跨多步執行**之後，工程師的角色換成三個職責：

① 指定意圖（specify intent）：把模糊的想法，寫成**精確到 agent 能可靠執行**的規格——讓它做你「真正想要的」，不是只做你「字面寫的」。
② 評估軌跡（evaluate trajectory）：不只看單一輸出對不對，而是看 agent **整條路徑**有沒有朝對的目標走。
③ 知道何時收回控制（take back control）：察覺 agent 走偏時，把手動控制權拿回來。

為什麼重要

關鍵在第②點：單一輸出可以「看起來對」，整條軌跡卻歪掉。例如一個 agent 正確修好了眼前的 bug，卻在過程中引入一個安全漏洞——輸出合格，軌跡有害。所以「評估軌跡」比「評估輸出」更要命，而這正是可信度／忠實度的核心問題。

而「把模糊意圖變成精確規格」不是軟實力，是**有可測產出影響的技術技能**，目前被嚴重低估。這條線接得起整站：意圖↔輸出落差就是職責①的微觀練習；而職責②（驗證生成內容是否真的可信）正是我 RAG 忠實度 研究在做的事。

出處：CSIC30216《AI-in-the-Loop in Software Project Cycle》Week 1 導論（Dennis Wang 王邦任、顏羽君），作者改寫重述。

一句話帶走

代理時代工程師的工作不是「會用 AI 工具」，而是：**指定意圖、評估軌跡、知道何時收回控制**。

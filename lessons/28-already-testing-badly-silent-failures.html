你早就在測了，只是測得爛：「試幾次覺得 OK」是一個爛測試套件，而最危險的失效是沉默的You're Already Testing — Just Badly: "Tried It a Few Times" Is a Weak Test Suite, and the Most Dangerous Failures Are Silent

「我在五個例子上試過，看起來不錯」——這已經是測試了，只是一個 size-5 的爛測試套件，有三個弱點：①那五個是寫 prompt 的人自己挑的、②沒人寫下「好」是什麼意思（憑感覺判）、③什麼都沒存，改完不能重跑。更要命的是：你最該抓的失效是沉默的——格式正確、讀起來合理、但答案是錯的。沉默失效只有在你先寫下「對」長什麼樣時才會現形。

"I tried it on five examples, looks good" — that already is testing, just a weak test suite of size 5 with three weaknesses: the five were chosen by the person who wrote the prompt; nobody wrote down what "good" means (judged by feel); nothing is saved, so you can't rerun after a change. Worse: the failures you most need to catch are silent — well-formed, plausible, and wrong. Silent failures only appear if you first wrote down what "right" looks like.

是什麼 · What it is

Week 10 講義的核心問句：「你怎麼知道你的 prompt 有用？」 用的例子是一個「從 diff 寫 commit message」的 prompt——你在五個 diff 上試過、看起來不錯，但你有多確定它在接下來 1,000 個 commit 上也行？講義的第一刀：「試五次」本身就是測試，只是爛測試。

「試五次」的弱點為什麼是問題
①那五個是你自己挑的選題偏誤——你挑的是你想得到的情況
②沒寫下「好」是什麼憑感覺判，無法重現、無法交接
③什麼都沒存改完 prompt 不能重跑，沒有回歸

一個測試套件，是你刻意去採樣三種變異：輸入（空 diff／2000 行 diff／含對 AI 喊話的 diff）、輸出（同一個 diff 這次跑和下次跑給不同訊息）、prompt 或模型（你改一句話、或供應商更新了模型）。「試五次」每一種都漏：你只試了典型輸入、每個只跑一次、只檢查了你自己寫的那版。

Week 10's core question: "How do you know your prompt works?" The running example is a prompt that writes a commit message from a diff — you tried five diffs and it looked good, but how confident are you about the next 1,000 commits? The lecture's first cut: trying it five times already is testing — just bad testing, a suite of size 5 with three weaknesses (self-chosen examples; no written definition of "good"; nothing saved to rerun). A real suite deliberately samples three kinds of variation — the input (empty diff / 2,000-line diff / a diff with a comment addressed to the AI), the output (the same diff gives a different message on another run), and the prompt-or-model (you reword a sentence; the provider updates the model) — and "five tries" misses each: you tried typical inputs, ran each once, and checked only the version you wrote.

為什麼重要 · Why it matters

講義把失效按「有多容易被發現」分成三種——這是這堂課最重要的一張表：

失效種類長什麼樣誰會發現
格式 Format輸出破壞了讀它的程式（被 code fence 包住、第一行 140 字）程式，大聲報錯
邊界 Edge case奇怪輸入得到壞結果（空 diff、超大 diff）程式或使用者，有時
沉默 Silent格式正確、讀起來合理、但就是錯的（給刪功能的 commit 寫「fix: update config」）沒有人，直到很久以後

關鍵一句（講義原文精神）：格式和邊界失效會「自己宣告」——只要你有檢查；沉默失效只有在你先寫下「對」長什麼樣時才會出現。 這就是 oracle 問題：沒有「正確答案的定義」，你看不見錯誤——所以 卡 26「寫下期望行為再測」不是形式主義，是唯一能抓到沉默失效的辦法。這也呼應 卡 24：判斷「對不對」本身需要一把先驗過的尺。

另外兩個講義重點，收進紀律：

  • prompt 測試 ≈ 軟體測試，但有三個關鍵差異。prompt 是用英文寫的 spec；一個 test case 是「輸入＋期望行為」（通常是一個性質，不是逐字文字）；而且非決定性——要重跑。甚至 temperature=0 也不保證逐字相同：講義舉 2025 一個實驗，同一個 prompt 在一個開源模型上跑 1,000 次給出 80 種不同輸出，肇因於服務端如何批次化請求，用 API 你管不到。所以「失敗的測試」有時是測試本身的 bug，不是 prompt 的。
  • 要有對照，也要承認極限。修完 prompt，旁邊跑一個「舊 prompt 的中性改寫」當對照：若改寫把結果移動得跟你的修法一樣多，你沒證明修法有效（呼應 卡 27）。而且 prompt 脆不脆弱不能用猜的：講義列了 Sclar 2023（改格式動 76 分）到 2026 多模型測試（強模型上格式常常不重要、但抽樣雜訊很大）的演變，結論只有一句——別宣稱脆或不脆，去量它。

一句話帶走 · Takeaway

「試幾次覺得 OK」已經是測試了，只是個爛的：自己選題、沒定義「對」、不能重跑。升級它，而且記住最該抓的失效是沉默的（格式對、讀來合理、答案錯），它只有在你先寫下「對」長什麼樣時才現形。prompt 測試像軟體測試，但非決定性（要重跑、連 temperature 0 都不保證相同）、期望的是行為性質不是逐字、而且失敗的測試有時是測試的 bug。別猜 prompt 脆不脆——去量。

"Tried it a few times, looks good" already is testing — just a bad test: self-chosen cases, no definition of "right," nothing to rerun. Upgrade it, and remember the failures that matter most are silent (well-formed, plausible, wrong); they only appear once you've written down what "right" looks like. Prompt testing is like software testing but non-deterministic (repeat it — even temperature 0 isn't guaranteed identical), the expectation is a behavioral property not exact text, and a failing test is sometimes a bug in the test. Don't guess whether your prompt is fragile — measure it.

好的「prompt builder」meta-prompt，其實是把忠實度、測試、失效診斷的紀律「編譯」成可重用的標籤A Good "Prompt-Builder" Meta-Prompt Is Just the Faithfulness, Testing, and Failure-Diagnosis Disciplines Compiled Into Reusable Tags

網路上流行的「用一個 master prompt 生出專家級 prompt」範本，看起來像魔法，拆開看其實不神秘：它把一串紀律固化成可重用的區塊——先問清楚再動手、不准編造、拆步、自我複審、寫測試連同「好結果長怎樣」、最後問「這會在哪裡失敗」。換句話說，一個好的 meta-prompt 不是咒語，是把你本來就該做的事編譯起來，讓你少漏幾項。但它是鷹架不是保證：它生出的 prompt 仍然要測、要量。

The popular "one master prompt that generates expert-level prompts" templates look like magic, but unpacked they're not mysterious: they bake a list of disciplines into reusable blocks — clarify before acting, never invent, decompose, self-review, write tests plus "what a good result looks like," and a final "where could this fail?" In other words, a good meta-prompt isn't a spell — it's the things you should already do, compiled, so you skip fewer of them. But it's a scaffold, not a guarantee: the prompt it produces still has to be tested and measured.

是什麼 · What it is

社群上（這張卡的引子是 IG 創作者 @sifuyik 一則「AI 訓練」懶人包裡的「Claude Master Prompt」）常見一種prompt builder：你丟一句粗略的需求，它幫你長成一個結構化的 prompt。它的價值不在那些字本身，而在它把一份檢查清單做成固定區塊。用我自己的話重述它涵蓋的動作：

  • 定角色與必要輸入：指名要什麼專家、明列它需要你先給的東西（受眾、來源、格式）。
  • 先問、別猜：缺資訊時最多問幾個關鍵問題、等你回答；不要靜默腦補去填空。
  • 拆步：任務大就切小，每步指名該由哪種專長處理。
  • 事實規則：只用你給的來源；確認過的事實、和「需要查證」的分開放；找不到就說「找不到」；絕不發明引述、數字、連結。
  • 自我複審：換一個「沒看過上文的 reviewer」視角，挑出模糊指令、矛盾、漏掉的題目。
  • 寫測試：給幾個測試輸入——一個正常、一個刁鑽、一個「AI 應該拒答或說不知道」的——並說出每個的好結果長什麼樣。
  • 輸出契約：講明輸出格式、長度、要附什麼。
  • 最後失效檢查：自問「這個 prompt 最弱的地方在哪？最可能在哪裡失敗？」列出 top 風險與各自的修法。

A common "prompt builder" (this card was prompted by the "Claude Master Prompt" slide in an AI-training carousel from IG creator @sifuyik): you give a rough request and it grows a structured prompt. Its value isn't the exact words but that it turns a checklist into fixed blocks. In my own rephrasing, it covers: define the expert role and required inputs; clarify before guessing (ask a few key questions, don't silently fill gaps); decompose big tasks by the expertise each step needs; fact rules (use only given sources, separate confirmed facts from "needs checking," say "not found," never invent quotes/numbers/links); self-review as a fresh reviewer; write test inputs — one normal, one tricky, one the AI should refuse or answer "I don't know" — and state what a good result looks like for each; an output contract; and a final "where is this prompt weakest / where could it fail?" risk check.

為什麼重要 · Why it matters

把這張範本和本站對照，會發現它整個就是這學期這條線的「編譯檔」——每個區塊都對到一張已經寫過的卡：

所以結論很樸素（作者觀點 Author's view）：一個好的 meta-prompt 不是魔法，是紀律被編譯成可重用的形狀。它的好處是真的——把好習慣前置，你就少漏幾項、不必每次憑記性。這呼應 卡 02：這是「prompt 層」的工程，把戰術固化成可重複的樣板。

但要守住兩條界線，別被行銷帶走：

  • 範本是鷹架，不是保證。它讓你比較不會跳過某個紀律，但它不量任何東西——它產出的還是一個 prompt，你仍然要照 卡 26 測、照 卡 28 定義「對」、照 卡 27 給分數加誤差棒。前置好習慣 ≠ 取代評估。
  • 「留言 PROMPT 領完整版」不是證據。互動數高不代表範本好。判斷一個 prompt 範本的唯一標準，是它的區塊有沒有對到真實的失效模式（而這張剛好有對到）——不是看它多少讚。這本身就是 卡 30「證據勝於斷言」的日常版。

一句話帶走 · Takeaway

一個好的「prompt builder」meta-prompt，其實就是把忠實度（不編）、先問別猜、拆步、自我複審、寫測試連同「好結果長怎樣」、以及最後「這會在哪裡失敗」的紀律，編譯成可重用的標籤。它把好習慣前置、讓你少漏幾項——很有用，但它是鷹架不是保證：它生出的 prompt 仍然要測、要量。判斷範本好壞看它有沒有對到真實失效模式，不是看它多少讚。

A good "prompt builder" meta-prompt is just the disciplines compiled into reusable tags — faithfulness (don't invent), clarify-before-guess, decompose, self-review, write tests plus "what a good result looks like," and a final "where could this fail?" It front-loads good habits so you skip fewer — useful, but a scaffold, not a guarantee: the prompt it produces still has to be tested and measured. Judge a template by whether its blocks map to real failure modes, not by how many likes it got.
